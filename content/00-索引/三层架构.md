# 三层架构

> 本知识库采用**原子-模块-流程**三层架构，充分利用 Obsidian 双链特性，实现知识的零重复、多层次理解和多视角导航。

---

## 核心理念

传统知识库的问题：
1. **知识点重复** - 同一个概念在多个文档中反复解释
2. **层次不清** - 基础概念和完整算法混在一起
3. **缺少复用** - 每个算法都从头讲起，无法看到共性
4. **视角单一** - 只能按算法类型浏览，缺少多维度入口

**三层架构的解决方案**：
- **原子层**：最小不可再分的知识点，被多个模块复用
- **模块层**：完整算法，由多个原子组合而成
- **流程层**：演化路径和应用场景，串联多个模块

```
03-流程 (Flow)      ← 演化路径、应用场景、决策流程
   ↓ 组合多个模块
02-模块 (Module)    ← 完整算法、方法族
   ↓ 组合多个原子
01-原子 (Atomic)    ← 最小不可再分知识点

00-索引 (Index)     ← 多维度入口
```

---

## 各层详解

### 01-原子 (Atomic Layer)

**定义**：最小不可再分的知识点，是构建模块的基础组件。

**特征**：
- 聚焦单一概念（如 Bellman方程、Clip机制、KL散度）
- 被多个模块引用（如 Clip机制 被 PPO、TRPO、GRPO 使用）
- 内容简洁（通常 100-200 行）
- 强调直觉理解和数学本质

**文档结构**：
```markdown
# [概念名]

> 一句话定义

## 核心思想
[简洁解释，100-200字]

## 数学表达
[关键公式 + 直觉解释]

## 被以下模块使用
- [[模块A]]
- [[模块B]]

## 优缺点
- ✅ ...
- ❌ ...

## 演化位置
[在历史脉络中的位置]
```

**示例**：
- [[01-原子/Bellman方程]] - 价值函数的递推关系
- [[01-原子/Clip机制]] - 限制策略更新幅度
- [[01-原子/KL散度]] - 衡量分布差异
- [[01-原子/策略梯度]] - 直接优化策略参数

---

### 02-模块 (Module Layer)

**定义**：完整的算法或方法族，由多个原子组合而成。

**特征**：
- 解决特定问题的完整方案（如 DQN、PPO、SAC）
- 引用多个原子，不重复其内容
- 包含算法流程、代码片段、应用场景
- 内容适中（通常 200-400 行）

**文档结构**：
```markdown
# [算法名]

> 一句话描述

## 组合构成
本模块由以下原子组合而成：
- [[原子A]] - 在本模块中的作用
- [[原子B]] - 在本模块中的作用

## 核心创新
[本模块独有的贡献，不重复原子内容]

## 算法流程
[伪代码或步骤]

## 代码片段
[关键实现代码]

## 优缺点
- ✅ ...
- ❌ ...

## 应用场景
- 适合：...
- 不适合：...

## 演化位置
[在流程中的位置，链接到 03-流程]
```

**示例**：
- [[02-模块/Value-Based/DQN]] = Q-Learning + 经验回放 + 目标网络 + 神经网络
- [[02-模块/Policy-Based/PPO]] = 策略梯度 + 优势函数 + GAE + Clip机制
- [[02-模块/Reward-Model/DPO]] = KL散度 + Bradley-Terry模型 + 隐式奖励

---

### 03-流程 (Flow Layer)

**定义**：演化路径、应用场景和决策流程，串联多个模块。

**特征**：
- 展示模块之间的历史演进（如 Value-Based 从 Q-Learning 到 DQN 到 Rainbow）
- 提供应用场景指南（如 如何根据问题选择合适的 RL 方法）
- 内容较长（通常 400-800 行）
- 包含演化图、对比表、决策树

**文档结构**：
```markdown
# [流程名]

> 一句话描述这条流程

## 演化全景
[时间线或演化图]

## 各阶段详解

### 阶段1：[模块A]
- 解决的问题
- 核心创新
- 链接：[[02-模块/模块A]]

### 阶段2：[模块B]
- ...

## 关键技术对比
[对比表]

## 应用场景指南
[如何根据场景选择模块]

## 延伸阅读
[相关流程和其他视角]
```

**示例**：
- [[03-流程/Value-Based演化史]] - 从 Bellman 到 Diffusion-RL
- [[03-流程/Policy-AC演化史]] - 从 REINFORCE 到 DAPO
- [[03-流程/Offline-RL与RLHF演化史]] - 从 BC 到 SimPO
- [[03-流程/场景选择决策树]] - 如何选择合适的 RL 方法

---

### 00-索引 (Index Layer)

**定义**：多维度入口页面，按不同视角组织知识。

**特征**：
- 提供多种浏览路径（按视角、按分类维度）
- 不重复内容，只提供导航
- 帮助读者从不同角度理解 RL

**示例**：
- [[00-索引/Policy视角]] - 从策略优化角度串联：策略梯度 → 优势函数 → Clip → PPO → GRPO
- [[00-索引/Reward视角]] - 从奖励建模角度串联：Pairwise RM → PRM → DPO → Verifiable Reward
- [[00-索引/按优化对象]] - Value-Based vs Policy-Based vs Actor-Critic
- [[00-索引/按策略类型]] - On-Policy vs Off-Policy

## 如何使用三层架构

### 学习路径

**路径1：由浅入深（推荐新手）**
```
00-索引 → 01-原子 → 02-模块 → 03-流程
```

1. 从索引页了解整体结构
2. 学习基础原子概念（Bellman方程、策略梯度等）
3. 理解完整算法（DQN、PPO等）
4. 掌握演化脉络（Value-Based演化史等）

**路径2：问题导向（推荐有经验者）**
```
03-流程/场景选择决策树 → 02-模块 → 01-原子
```

1. 根据问题场景找到合适的算法
2. 学习该算法的完整内容
3. 深入理解其使用的原子概念

**路径3：视角浏览（推荐研究者）**
```
00-索引/Policy视角 → 03-流程 → 02-模块
```

1. 从特定视角（如 Policy）浏览相关概念
2. 理解该视角下的演化脉络
3. 深入学习具体算法

### 查找知识

**想找某个概念？**
- 使用 Obsidian 的搜索功能（Ctrl+Shift+F）
- 或在 [[00-索引/README]] 中查找

**想理解某个算法？**
- 直接打开 [[02-模块/]] 中的对应文档
- 查看其"组合构成"，了解使用了哪些原子
- 点击原子链接，深入理解基础概念

**想了解演化历史？**
- 打开 [[03-流程/]] 中的对应文档
- 查看演化图，理解各阶段的关系

## 架构优势

### 1. 零重复
每个概念只写一次，通过双链复用。例如：
- [[01-原子/Clip机制]] 只写一次
- [[02-模块/Policy-Based/PPO]]、[[02-模块/Policy-Based/TRPO]]、[[02-模块/Policy-Based/GRPO]] 都引用它
- 更新 Clip机制 的解释，所有模块自动受益

### 2. 多层次理解
- **快速浏览**：只看模块的"组合构成"，了解算法由哪些部分组成
- **深入理解**：点击原子链接，学习基础概念
- **全局视角**：通过流程层，理解算法之间的演化关系

### 3. 多视角导航
- **Policy视角**：从策略优化角度串联知识
- **Reward视角**：从奖励建模角度串联知识
- **分类维度**：按优化对象、策略类型、动作空间等分类

### 4. 易于扩展
- **新增原子**：如果一个概念被 3 个以上模块使用，考虑提取为原子
- **新增模块**：完整算法，引用相关原子
- **新增流程**：演化路径或应用场景，串联相关模块

### 5. 充分利用 Obsidian 双链
- 知识点之间的关系清晰可见
- 在 Obsidian 的图谱视图中，可以看到原子-模块-流程的层次结构
- 通过反向链接，可以快速找到"哪些模块使用了这个原子"

## 维护指南

### 新增原子
1. 在 [[01-原子/]] 中创建文档
2. 使用原子文档模板
3. 在相关模块中添加引用

### 新增模块
1. 在 [[02-模块/]] 的对应类别中创建文档
2. 使用模块文档模板
3. 明确列出"组合构成"，引用相关原子
4. 在相关流程中添加链接

### 新增流程
1. 在 [[03-流程/]] 中创建文档
2. 使用流程文档模板
3. 串联相关模块，展示演化脉络
4. 在 [[00-索引/README]] 中添加链接

### 更新链接
- 使用 `[[路径/文档名]]` 格式
- 保持双链完整，避免断链
- 定期检查 Obsidian 的"未链接提及"功能，发现潜在链接

## 示例：理解 PPO

### 从模块层开始
打开 [[02-模块/Policy-Based/PPO]]，看到：

```markdown
## 组合构成
- [[01-原子/策略梯度]] - 直接优化策略参数
- [[01-原子/优势函数]] - 降低策略梯度方差
- [[01-原子/GAE]] - 广义优势估计，平衡偏差-方差
- [[01-原子/Clip机制]] - 限制策略更新幅度
- **Actor-Critic架构** - Actor学习策略，Critic学习价值函数
```

**快速理解**：PPO = 策略梯度 + 优势函数 + GAE + Clip机制 + Actor-Critic

### 深入原子层
点击 [[01-原子/Clip机制]]，学习：
- 为什么需要限制策略更新幅度
- Clip 的数学表达
- 与 TRPO 的信任区域的对比

### 查看演化脉络
打开 [[03-流程/Policy-AC演化史]]，看到：
```
策略梯度 → REINFORCE → Actor-Critic → TRPO → PPO → GRPO → DAPO
```

**全局理解**：PPO 是 Policy-AC 演化链中的一个关键节点，前承 TRPO，后启 GRPO。

## 总结

三层架构的核心价值：
1. **零重复** - 每个概念只写一次
2. **多层次** - 原子→模块→流程，由浅入深
3. **多视角** - Policy视角、Reward视角、分类维度
4. **易扩展** - 新增原子/模块/流程，自动受益
5. **双链驱动** - 充分利用 Obsidian 的关系图谱

这种架构让知识库不仅是文档的集合，而是一个**有机的知识网络**，每个节点都有明确的位置和关系。
